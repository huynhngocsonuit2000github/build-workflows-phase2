### 3.2 Domain

**Project**

| Trường | Kiểu | Quy tắc |
|---|---|---|
| `Id` | int, tự tăng | |
| `Name` | string | Bắt buộc, cắt khoảng trắng hai đầu, dài 1–100 ký tự |
| `MemberIds` | `List<string>` | EF Core primitive collection (lưu dạng JSON). Người tạo luôn được thêm vào. Bỏ trùng; mỗi id không rỗng, tối đa 50 ký tự |
| `CreatedAt` | DateTime (UTC) | |

**TaskItem**

| Trường | Kiểu | Quy tắc |
|---|---|---|
| `Id` | int, tự tăng | |
| `ProjectId` | int, FK → Project | |
| `Title` | string | Bắt buộc, cắt khoảng trắng hai đầu, dài 1–200 ký tự |
| `Status` | enum `TaskItemStatus` = `Todo`, `InProgress`, `Done` | Lưu dạng string. Task mới luôn là `Todo` |
| `Assignee` | string? | Nếu có, phải là thành viên của project |

Đổi trạng thái: cho phép đổi sang bất kỳ giá trị nào trong 3 giá trị trên. Giá trị khác thì trả 400. Enum trong JSON viết dạng chuỗi (`"InProgress"`), dùng `JsonStringEnumConverter`.

### 3.3 Phân quyền giả lập

- Đọc user hiện tại từ header `X-User-Id`. Thiếu hoặc rỗng: **401** (ProblemDetails).
- Project không tồn tại: **404**. Project có nhưng user không phải thành viên: **403**.
- Làm bằng một endpoint filter và một helper. Không dùng authentication scheme của ASP.NET.

### 3.4 Endpoint

Mọi endpoint đều yêu cầu `X-User-Id`. Request và response dùng DTO dạng record, không trả entity ra ngoài.

| Method | Route | Body | Thành công | Ghi chú |
|---|---|---|---|---|
| POST | `/projects` | `{ name, memberIds? }` | 201 + Location | Người tạo tự động là thành viên |
| GET | `/projects` | | 200 | Chỉ các project mà user là thành viên (để web làm danh sách chọn) |
| GET | `/projects/{projectId}` | | 200 | Chỉ thành viên |
| POST | `/projects/{projectId}/tasks` | `{ title, assignee?, dueDate? }` | 201 + Location | Chỉ thành viên; status = `Todo` |
| GET | `/projects/{projectId}/tasks` | | 200 | Chỉ thành viên; trả toàn bộ, sắp theo `Id` tăng dần, **không** phân trang, **không** lọc |
| GET | `/projects/{projectId}/tasks/{taskId}` | | 200 | 404 nếu task không thuộc project |
| PATCH | `/projects/{projectId}/tasks/{taskId}/status` | `{ status }` | 200 + task | Chỉ thành viên |

Thêm `GET /health` trả `{ "status": "ok" }`, không cần header.

### 3.5 Lỗi

- `builder.Services.AddProblemDetails()`. Lỗi validation trả **400** dạng `ValidationProblem` (có `errors` theo từng trường). Có thể dùng validation tích hợp của .NET 10 (`AddValidation()`) hoặc tự kiểm tra rồi trả `Results.ValidationProblem`. Chọn một cách và dùng thống nhất.
- 401, 403, 404 đều trả ProblemDetails (`Results.Problem(statusCode: …)`), không trả body rỗng.

### 3.6 Dữ liệu, migration, cấu hình

- Connection string trong `appsettings.json`: `Data Source=tasklite.db`. File `.db` không commit.
- Cài `dotnet-ef` dạng local tool (`dotnet new tool-manifest`, `dotnet tool install dotnet-ef`), rồi tạo migration `InitialCreate`.
- Khi chạy môi trường Development: tự gọi `Database.Migrate()` lúc khởi động, sau đó `DevSeeder` thêm dữ liệu mẫu **nếu DB đang trống**: project `Demo` có thành viên `alice`, `bob`, kèm 3 task (mỗi status một task, một task giao cho `bob`).
- `launchSettings.json`: profile `http` chạy ở `http://localhost:5200`, bỏ profile https cho đơn giản.
- OpenAPI tích hợp sẵn (`AddOpenApi()`, `MapOpenApi()` khi Development). Không cài Swagger UI.
- CORS: cho phép origin đọc từ cấu hình `Cors:AllowedOrigins` (mặc định `["http://localhost:4300"]`), cho phép mọi header (cần cho `X-User-Id` và `Content-Type`) và các method GET, POST, PATCH.

### 3.7 File `.http`

`TaskLite.Api.http` có biến `@baseUrl = http://localhost:5200`. Mỗi request có tiêu đề `###`, phủ đủ các tình huống:
1. Tạo project bằng `alice`, có thêm thành viên `bob`.
2. Liệt kê project của `alice`.
3. Tạo task, có và không có `assignee`.
4. Liệt kê task.
5. Đổi status sang `InProgress`, rồi `Done`.
6. Lỗi: thiếu `X-User-Id` → 401; `mallory` đọc task → 403; project không tồn tại → 404; title rỗng → 400; assignee không phải thành viên → 400; status `Archived` → 400.
